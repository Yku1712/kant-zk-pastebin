# INT07-24 — Minimal integration design

**Experimental patch VERIFIED locally. Live integration BLOCKED. NOT PRODUCTION-READY.**

## Actual source paths

- **Authorized snapshot and release.** Artifact MCP at `731d5b6e3436cc4bdee961f8510eda6ea2a0d9eb` exposes typed reads through `ArtifactService` and `AccessPolicy`. The normal bridge entry should obtain the publisher or viewer grant, resolve the tenant and the exact current or historical revision, and bind the bytes and metadata within a consistent lifecycle boundary. The reviewed `read_body_for` and `read_revision_body_for` recheck readiness; they do not cover acquisition of the earlier grant plus an external send. `hidden` affects lists and share tokens grant read access. The export needs an independent release decision scoped to source, tenant, artifact, revision, digest and destination. [Artifact port](https://github.com/meta-introspector/artifact-mcp/blob/731d5b6e3436cc4bdee961f8510eda6ea2a0d9eb/src/ports/artifacts.rs#L20) · [Access policy](https://github.com/meta-introspector/artifact-mcp/blob/731d5b6e3436cc4bdee961f8510eda6ea2a0d9eb/src/security/access.rs#L441) · [Read implementation](https://github.com/meta-introspector/artifact-mcp/blob/731d5b6e3436cc4bdee961f8510eda6ea2a0d9eb/src/artifacts/lifecycle/api.rs#L15)
- **Upload and durable identity.** Fork Pastebin `upload_file` begins with lossy UTF-8 processing for multipart and strips delimiters/whitespace, which can change original bytes. It writes a timestamp/slug spool file, attempts IPFS, checks then creates a pseudo-CID alias, and appends to an index separately. `create_paste_inner` uses text/RDFa records and can return after best-effort writes. Neither path accepts a durable idempotency key, performs atomic operation correlation, or provides read-only lookup by operation. An alias hit or repeated timestamp cannot authenticate a matching operation. [Route registration](https://github.com/Yku1712/kant-zk-pastebin/blob/d53b4ca8cafbaea5cf11bbb508bb75ced5081585/src/main.rs#L502) · [Upload](https://github.com/Yku1712/kant-zk-pastebin/blob/d53b4ca8cafbaea5cf11bbb508bb75ced5081585/src/upload_handler.rs#L16) · [Paste creation](https://github.com/Yku1712/kant-zk-pastebin/blob/d53b4ca8cafbaea5cf11bbb508bb75ced5081585/src/handlers.rs#L439)
- **Receipt identity and bytes.** Pastebin returns a timestamp/slug ID, local alias, SHA-256 witness, and optional CID. `get_paste` renders a spool record and `get_file` resolves filesystem entries by name. Neither correlates independent original bytes to an authenticated bridge operation. [Response type](https://github.com/Yku1712/kant-zk-pastebin/blob/d53b4ca8cafbaea5cf11bbb508bb75ced5081585/src/model.rs#L16) · [Read handlers](https://github.com/Yku1712/kant-zk-pastebin/blob/d53b4ca8cafbaea5cf11bbb508bb75ced5081585/src/handlers.rs#L633)
- **UnixFS.** `ipfs_proxy` calls `ipfs_cat`, which returns a single flatfs block selected by CID multihash. It does not verify a full graph or reconstruct UnixFS. The fork's block writer can report a root after missing or failed writes. The audited upstream baseline suppresses the root after detected block-write failures, but also has single-block reads. [Fork IPFS](https://github.com/Yku1712/kant-zk-pastebin/blob/d53b4ca8cafbaea5cf11bbb508bb75ced5081585/src/ipfs.rs#L64) · [Audited upstream IPFS](https://github.com/meta-introspector/kant-zk-pastebin/blob/13d92d97b9b89f9af94a35cb70436035bd2fd05a/src/ipfs.rs#L65)

## Smallest compatible change

1. Keep public HTTP routes unchanged. Start with in-process or authenticated internal source and destination adapters. Authorize a single-file revision and check length and SHA-256 before admitting a publication intent. Fail closed for a denied, missing or stale release.
2. Define destination submit, lookup and readback around one immutable operation record. Use one transaction to admit a new operation alongside its original bytes or an independently verified durable content reference. On repeated submission require the same full binding and bytes and return the original receipt. Use a read-only operation lookup and fetch original bytes separately from the submission response.
3. If a future destination uses IPFS, bind its expected root and CID presence to the authoritative operation record. Fetch each linked block, verify the multihash against its requested CID, decode only supported UnixFS file nodes and codecs, follow all ordered links, validate sizes, and bound bytes, node count, depth and time. Compare the reconstructed digest to the authoritative source. A failed storage write, missing child, incomplete reconstruction, absent required CID or ambiguous transport outcome remains UNRESOLVED. IPFS-only confirmations require this proof even when spool bytes match.
4. Keep the bridge journal and destination transaction separate. Allow retry only after verifying provider-wide idempotency under concurrent original submissions, restarts and lost responses. With the current routes, an ambiguous outcome requires independent evidence and cannot trigger a blind second POST.

The [experimental patch](INT07_24_EXPERIMENTAL.patch) adds a standalone Rust crate and tests under `agent2/experimental/`. Its SQLite store models atomic operation correlation and bytes, scoped lookup, separate read-only byte verification and a bounded payload. Its instance identity is bound to a dedicated local database, with local trust in the configured path. The crate opens no transport and explicitly rejects IPFS evidence. The patch does not alter Pastebin or Artifact MCP routes, and uses only public dependencies. Its tests inject a lost response above a real destination database commit.

An actual Pastebin build is **BLOCKED** by the four authentic `nora` dependencies (`rust-unixfs`, `ipld-dagpb`, `quick-protobuf`, and `erdfa-publish`). No replacement or registry bypass was used. A live source/release provider, a service-backed receipt contract, and full UnixFS readback are also **BLOCKED**. The local experiment supplies no evidence for those live interfaces.
