## Review findings

- **Release enforcement depends on the adapter.** `Publisher::execute` checks the supplied snapshot and invokes the policy, but principal and release provenance enter through trusted traits. Source inspection found no native proof handle that keeps authorization valid across dispatch. Require an immutable release record for the exact binding, or a revocation-aware guard covering dispatch.
- **Retry eligibility is an integration contract.** The default retry does nothing. An override of `retry_idempotently` is callable when the operator selects that mode and lookup returns no result. The interface supplies no independently issued durable-idempotency capability. Keep existing Pastebin routes in lookup-only mode. The experimental destination has a separately tested single-transaction contract.
- **Receipt and CID trust are split.** A CID plus matching payload bytes does not establish a DAG traversal. The DAG-PB proof is delegated to `ReceiptEvidence`, and a CID is optional in the candidate. An IPFS-required destination must require a CID from its authoritative record and authenticate the root before confirmation.
- **Resource and journal boundaries need deployment controls.** The API borrows an entire source body and accepts whole readback vectors. It also trusts its local journal as the persistence authority for existing confirmed receipts. Require bounded transport/readback and a dedicated journal protected by OS access controls.
